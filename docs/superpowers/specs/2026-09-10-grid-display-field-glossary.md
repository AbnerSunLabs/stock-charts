# 网格页展示字段口径（歧义对照）

> 日期：2026-09-10  
> 范围：`/view/grid` 计算器、组合看板、成交流水里**仍待改**的数字与文案  
> 状态：已落地项与不用改的项已从本文删除  
> 相关：[`docs/grid-strategy-design.md`](../../grid-strategy-design.md)、[`2026-09-09-grid-portfolio-journal-design.md`](./2026-09-09-grid-portfolio-journal-design.md)、[`2026-09-10-grid-align-last-step-design.md`](./2026-09-10-grid-align-last-step-design.md)

本文只解释「用户看到的数字是按哪套规则算的」。例子里的金额、股数是为了对账编的，不是某次真实策略。

默认成本假设（与代码默认一致）：ETF 佣金万 1、`minCommission = 0`、无印花税、无过户费。

---

## 0. 怎么读

改动标记：

| 标记         | 含义                                                          |
| ------------ | ------------------------------------------------------------- |
| **要改数字** | 同一屏上的数对不上，或和已定 spec 不一致，必须改计算/展示逻辑 |
| **要改交互** | 公式未必错，但操作会把账记到错误档位                          |
| **只改文案** | 公式对，标签或 Tooltip 不够，用户会理解错                     |

每个字段另写：出现位置、当前实现、例子、建议口径。

「计划值」来自计算器生成的档位快照；「成交值」来自成交流水。二者本来就不是同一件事。

## 2. 买入金额 / 预计最大投入（佣金） · **要改数字**

> 只改单档和展开子行的「买入金额」；KPI 与折叠组合行不用改。

### 出现位置

- 计算器主 KPI、看板 KPI：「预计最大投入」
- 结果表列：「买入金额」

### 当前实现

| 位置                                 | 公式                                   |
| ------------------------------------ | -------------------------------------- |
| KPI / 压力测试 `totalBudgetRequired` | Σ(`actualBuyAmount` + `buyCommission`) |
| 折叠组合行                           | 同上（组内汇总）                       |
| 单档行、展开后的子行                 | 只有 `actualBuyAmount`                 |

规格 4.7.4 规定组合行金额含佣金；明细行目前没对齐。

### 例子

同一组两档被聚合成一行：

|          | 实际买入金额 | 买入佣金（万 1） |
| -------- | -----------: | ---------------: |
| 小网档 A |    10,000.00 |             1.00 |
| 中网档 B |    15,000.00 |             1.50 |

用户会看到：

| 位置                                         |     显示 |
| -------------------------------------------- | -------: |
| 主 KPI「预计最大投入」（若全策略只有这两档） | 25,002.5 |
| 折叠组合行「买入金额」                       | 25,002.5 |
| 展开后 A 行                                  |   10,000 |
| 展开后 B 行                                  |   15,000 |
| 用户心算 A+B                                 |   25,000 |

差 **2.5**。把整张表明细加总，也会比顶部 KPI 少全部买入佣金。万 1 时单档只差几块钱，档位一多就会觉得「加总对不上」。

### 建议口径（待确认）

结果表「买入金额」一律含买入佣金，与 KPI 相同。表头或 Tooltip 写清「含佣金」。不要把 KPI 改成不含佣金——资金压力本来就要含成本。

## 3. 预计最大投入（计算器 vs 看板） · **只改文案**

> 两边公式都对，不是同一个数据源。看板标签标明「已保存」即可。

### 出现位置

两边标签都叫「预计最大投入」。

### 当前实现

| 位置            | 数据源                                                      |
| --------------- | ----------------------------------------------------------- |
| 计算器 KPI      | **当前页面**刚生成的 `stressTest.v2.totalBudgetRequired`    |
| 看板 KPI / 卡片 | 各策略 **最近一次保存** 的 `resultSnapshot.stressTest` 之和 |

未点「更新策略」时，这两边可以不是同一个数。这是实现如此，不是公式写错；标签没有标明「已保存」。

### 例子

策略「沪深 300 网格」已保存投入 150,000。打开后改最低价并点「重新生成」，计算器显示 180,000。还没保存。

| 位置                                       |    显示 |
| ------------------------------------------ | ------: |
| 计算器 Tab「预计最大投入」                 | 180,000 |
| 看板 Tab 该卡 + 顶栏合计（仅这一份策略时） | 150,000 |

用户来回切 Tab 会以为刷新丢了 3 万。看板顶栏是多策略合计，再叠一份未保存草稿，差得更远。

### 建议口径（待确认）

看板保持「已保存快照」——组合看的是落库策略。标签改为「已保存预计最大投入」，或在未保存时提示计算器结果尚未写入看板。

## 4. 流水盈利金额（成交日 vs 记账先后） · **只改文案**

> FIFO 按 `createdAt` 与 spec 一致，不要改成按成交日配对。

### 出现位置

流水表按成交日从新到旧排；盈利按 `createdAt` FIFO。

### 当前实现

规格写的是按 `created_at` 配对。补录、倒填成交日时，表格从上往下的顺序不必等于配对顺序。

### 例子

同一档三笔：

| 记账时间 createdAt | 成交日 | 方向 |   价 |  量 |
| ------------------ | ------ | ---- | ---: | --: |
| 09-01 10:00        | 09-10  | 买   | 1.00 | 100 |
| 09-02 10:00        | 09-01  | 买   | 1.20 | 100 |
| 09-03 10:00        | 09-11  | 卖   | 1.30 | 100 |

表格按成交日：先看到 09-01 买 1.20，再 09-10 买 1.00，再 09-11 卖 1.30。  
按屏幕会以为卖的是 1.20 那笔：盈利 `(1.30 − 1.20) × 100 = 10`。

FIFO 按记账先后：先匹配 1.00 那笔：

```text
盈利 = (1.30 − 1.00) × 100 = 30
```

### 建议口径（待确认）

继续按 `createdAt`（与 spec 一致）。盈利列说明写成「按记账先后配对，不是按成交日」。

## 5. 未保存重新生成 vs 流水档位 · **要改交互**

不是某一个 KPI 字段，但会让「档位」列对不上。

记账按钮用**当前计算器**的 `leg.id` 和价格；流水/看板解析档位文案用**已保存快照**的 legs。

### 例子

已保存档 `small-0-3`，买价 0.850，position 0.85。改步长后重新生成，同一 id 槽位买价变成 0.840，position 0.84，尚未保存。此时点「买入」：

| 位置         | 用户看到                                              |
| ------------ | ----------------------------------------------------- |
| 结果表该行   | 买价 0.840，档位 0.84                                 |
| 弹窗默认价   | 0.840                                                 |
| 流水「档位」 | 仍按保存快照显示 **0.85**（id 撞车）或 `-`（id 已变） |
| 看板档位数 b | 仍是旧快照的档数                                      |

### 建议口径（待确认）

有未保存结果时禁用记账，或必须先「更新策略」。
