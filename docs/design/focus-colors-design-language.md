# 项目通用设计语言

本规范适用于项目内所有新建或调整的页面，包括列表、表单、详情、工作台和数据展示页。目标是让不同功能共享同一种视觉风格，同时根据各自任务安排内容。

视觉基准来自 `output/index-levels-exploration/linked-demos/05-focus-colors.html`；这里只提取跨页面规则。配套参考样式见 [focus-colors-core.css](focus-colors-core.css)。本规范与该 CSS 是项目现役视觉依据；不代表全站已经完成迁移。

**设计基调：柔和、清晰、克制。低饱和背景承托内容，留白建立分组，字阶表达重点，靛紫色标识操作与选择。**

## 一、布局规则

### 页面骨架

- 内容采用居中的流式容器，最大宽度 1440px，宽度包含内边距。
- 页头统一表达页面身份：标题为主，辅助说明可选，相关操作按需放在右侧。没有必要时不添加说明或操作。
- 页面主体由主要任务决定，可以是单栏、并列区域或主次布局；不强制出现摘要、图表、筛选器等模块。
- 主内容使用白色连续画布。相关内容尽量放在同一画布中，借助间距与小标题建立分组。
- 补充内容可使用浅灰表面；需要柔和强调的上下文内容可使用淡紫表面。背景色表达层级，不用于给每种业务分配专属颜色。
- 同级模块对齐外边缘、标题起点和内容起点。并列区域按内容需要决定比例，不统一规定为两列。
- 容器嵌套保持克制，避免每个字段、每段文本都单独套卡片。

### 响应式

- 720px 是基础紧凑布局断点：页头与操作区允许纵向排列，表单控件可撑满容器，多列区域按可读性改为单列。
- 更宽视口是否需要重排由内容最小可用宽度决定，不把某个页面的列数作为全局要求。
- 文本优先换行，操作组允许折行；不可通过无限缩小字号维持桌面布局。
- 表格等确需横向浏览的内容在自己的容器内滚动，避免整页横向溢出。
- 图表、编辑器等专用内容的高度、比例与操作方式由页面另行定义。

## 二、排版规则

使用系统无衬线字体，不额外引入字体依赖。数字对齐、编号或时间序列确有需要时使用等宽数字或系统等宽字体。

| 视觉角色 | 字号 / 字重 | 行高与使用方式 |
| --- | --- | --- |
| 页面标题 | 20px / 600 | 1.4，字距 -0.025em |
| 区域标题 | 20px / 600，紧凑区域可用 15px / 600 | 1.4；同级标题保持一致 |
| 关键展示值（可选） | 44px / 600，紧凑布局 36px | 1，字距 -0.045em；只用于需要突出的少量内容 |
| 默认正文 | 14px / 400 | 1.6 |
| 长文本阅读 | 15px / 400 | 1.9；保持舒适行宽，允许自然折行 |
| 控件文字、辅助内容 | 13px / 400–500 | 约 1.5；选中项可用 600 |
| 标签、元信息 | 12px / 400–500 | 约 1.5；仍需清晰可读 |

- 文字三级：重点 `#30334b`、正文 `#4b526c`、辅助 `#69718a`。正文不依赖低透明度实现层级。
- 标题、关键值与选中项承担主要字重，其余内容保持正常字重。
- 同一数据列保持格式和对齐一致。大展示值可以使用比例数字；需要纵向比较的数列使用 `tabular-nums`。
- 页面可以没有大数字；不可为了套用模板人为制造关键指标。
- 重要操作、表单标签和正文不采用 10–11px 的图内标注字号。

## 三、空间规则

以 4px 为常用步长，使用 4 / 8 / 12 / 16 / 20 / 24 / 28 / 32px。参考界面中的局部校正值不作为必须复制的全局约束。

| 关系 | 基准值 |
| --- | --- |
| 页面内边距 | 桌面上 24、左右 32、下 32px；紧凑布局上 24、左右 14、下 28px |
| 页头至主体 | 20px |
| 容器内边距 | 桌面 24px，紧凑布局 16px |
| 主要模块之间 | 桌面 20–24px，紧凑布局 16–20px；同页选定一档保持一致 |
| 分组之间 | 24–32px |
| 标题与内容 | 12–16px |
| 同组控件、图标与文字 | 8–12px |
| 标签与输入区域 | 6–8px |

- 同组紧、跨组松。间距应表达内容关系，不用于填满空白。
- 卡片圆角 12px，输入控件 8px，紧凑按钮 6px，分段选择器 999px。
- 优先用背景与留白建立边界，细分隔线只用于需要逐行比较或明确边界的内容。
- 主容器保持平面，无常驻装饰阴影。轻阴影用于浮层、选中项和操作反馈。

## 四、交互规则

视觉状态统一，状态变化的业务含义由实际组件决定。

| 状态 | 统一表现 |
| --- | --- |
| 默认 | 中性色文字、白底或浅色底，必要时使用细边框 |
| 悬停 | 靛紫文字、浅紫底或稍深背景；链接颜色加深 |
| 选中 | 浅紫底、紫色描边、深紫文字；分段选择器使用白色选中面 |
| 按压 | 可独立移动的按钮可缩放至 0.96，并使用内阴影 |
| 键盘焦点 | 2px 靛紫焦点环，向外偏移 4px，不只依靠颜色变化 |
| 禁用 | 透明度 0.45，取消位移与阴影；原生控件同时设置 disabled |

- 普通过渡使用 300ms；颜色、边框、背景、阴影平滑变化，不对尺寸或布局做无关动画。
- 有独立空间的按钮可沿用上移 4px 与紫色柔影的悬停反馈。密集表格操作、分段器、输入控件和文字链接保持原位；该位移是可选修饰，不是所有控件的强制行为。
- 悬停位移仅用于支持 hover 且未要求减少动效的设备。减少动效时取消过渡和变形。
- 单选、多选、开关、内容标签页分别使用符合其语义的状态属性；是否允许再次点击取消，由组件任务决定。
- 所有操作提供键盘入口；选中态不替代焦点态。触控不能依赖 hover 才出现唯一操作入口。
- 链接保留可识别文案。是否新开标签页由目标及任务决定，不在设计系统中统一强制。
- 加载、空内容、失败和校验反馈沿用同一字阶、间距和表面色；重要提示要有文字说明，不能只换颜色。

## 五、组件规则

组件按视觉职责复用，页面只采用实际需要的组件。

| 组件 | 通用约束 |
| --- | --- |
| 页面容器 | 居中、最大宽度 1440px、统一页边距 |
| 页头 | 标题与可选说明为一组，相关操作为一组；窄屏自然重排 |
| 主内容容器 | 白底、12px 圆角、24/16px 内边距、无装饰性描边和阴影 |
| 次级容器 | `#f8fafc` 底、同类圆角和间距；用来承载辅助内容 |
| 柔和强调面板 | `#f7f7ff` 底，用于与主内容相关的解释或上下文；可以独立放置，不绑定固定位置 |
| 按钮 | 紧凑圆角 6px、水平内边距 12px、最小高 40px；紧凑工具按钮可用 36px |
| 主要按钮 | 靛紫底、白字；每个操作组保持明确主次，避免多个同等强度主按钮 |
| 次要按钮 | 白底细边或浅紫底、紫字；选择按钮选中后使用浅紫底与紫色边框 |
| 输入框、选择器 | 最小高 40px、8px 圆角、灰底细边；聚焦变白、紫边与柔和光晕；宽度由内容与布局决定 |
| 分段选择器 | 灰绿胶囊轨道、内边距 4px；选项最小高 32px、左右 14px；选中白底、深字、轻影 |
| 长文本 | 15px / 1.9；可用细淡紫左线表达引用或附属说明，普通正文不强制加线 |
| 浮层与提示 | 近白表面、细灰边、12px 圆角、轻影、12–14px 文字；定位与关闭行为由组件负责 |
| 列表与表格 | 复用正文、辅助字色、细边和留白；密度按阅读任务决定，避免给每行增加独立卡片 |

### 色彩职责与令牌

| 职责 | CSS 变量 | 色值 |
| --- | --- | --- |
| 页面背景 | `--page-bg` | `#f1f5f9` |
| 主表面 | `--surface` | `#ffffff` |
| 次级表面 | `--surface-subtle` | `#f8fafc` |
| 柔和强调表面 | `--surface-tint` | `#f7f7ff` |
| 重点 / 正文 / 辅助文字 | `--text-strong` / `--text-body` / `--text-muted` | `#30334b` / `#4b526c` / `#69718a` |
| 主色 / 深色操作 / 深色文字 | `--primary` / `--primary-active` / `--primary-ink` | `#6366f1` / `#4f46e5` / `#4338ca` |
| 选中浅底 / 加深浅底 | `--selection-bg` / `--selection-hover` | `#eef2ff` / `#e0e7ff` |
| 普通 / 选中描边 | `--border` / `--border-selected` | `#e2e8f0` / `#a5b4fc` |
| 控件底 / 分段器轨道 | `--control-bg` / `--segment-bg` | `#eef2f7` / `#eef1ef` |

主色集中用于操作、链接和选择，避免整页大面积饱和紫色。图形可沿用柔和靛紫 `#8183d8` 和浅网格 `#eceff8`，具体系列及尺寸由可视化任务决定。

红、绿、琥珀属于按需使用的语义色，不是每页必须出现的配色。其含义由对应领域约定，并配合文本或图标表达；本规范不规定它们必须代表某种业务状态。

## 跨页面落地方法

1. 先确定本页的主要任务、信息层级与必需操作，再选择单栏、并列或主次布局。
2. 使用本规范的颜色、字阶、间距与圆角，不从参考页复制业务模块、字段或固定图形尺寸。
3. 将已有组件映射到相应视觉职责；同类组件跨页面保持相同外观和状态反馈。新增组件沿用同一组令牌。
4. 表单页围绕字段组与提交操作组织；列表页围绕查询与结果组织；详情页围绕主内容与辅助信息组织。它们共享视觉规则，各自保留合适的结构。
5. 验收桌面与窄屏的对齐、层级、可读性、溢出，以及默认、悬停、选中、按压、焦点和禁用状态。

核心 CSS 是带 `.focus-design` 作用域的通用参考，不接入生产页面。类名表达视觉职责；可映射到现有组件，无需为使用此规范统一改名。主要按钮与输入框等是沿现有设计语言归纳的通用用法，并非声称参考页已展示全部组件。宿主页负责 reset；独立 HTML 应设置 `body { margin: 0; }`。JavaScript 行为、路由、数据、文案和业务校验由各页面自行负责。
